# ССП, лабораторная работа 5. Как запустить

Тема: **Многопоточное и асинхронное программирование** (часть 1: Producer-Consumer, Mutex, Semaphore, deadlock; часть 2: TPL, параллельные циклы, PLINQ, разделение данных). Код находится в папке `Lab5`, **все задания собраны в один проект**, нужное задание выбирается аргументом.

## Что нужно установить (один раз)

| Что | Зачем | Как проверить |
|---|---|---|
| **.NET SDK 10** | компиляция и запуск C# | `dotnet --version` (должно быть `10.x`) |
| **Visual Studio 2022/2026** (или VS Code с C# Dev Kit) | показать окна отладчика Parallel Stacks, Threads, Call Stack (задание про deadlock) | в Visual Studio есть меню Debug |
| *по желанию* `dotnet-stack` | стеки потоков из консоли (`dotnet tool install --global dotnet-stack`) | `dotnet-stack --version` |

## Запуск

```bash
git clone https://github.com/KsushaKhadzhinova/ssp.git
cd ssp
git checkout lab-5
cd Lab5
dotnet run -c Release -- pc
```

Режим – слово после `--`. **Всегда запускайте в Release**: в Debug замеры времени получаются другими.

## Таблица режимов

| Команда | Что выполняется | Время работы |
|---|---|---|
| `dotnet run -c Release -- pc` | часть 1, задание 1: Producer-Consumer, буфер 5, 2 производителя, 3 потребителя | 5 с |
| `-- pc2` / `-- pc10` | задание 2: размер буфера 2 / 10 | 5 с |
| `-- pc-more` | задание 3: 3 производителя и 4 потребителя | 5 с |
| `-- pc-items` | усложнённое задание: в буфере объекты `DataItem` | 5 с |
| `-- deadlock` | **зависает по замыслу** (искусственный deadlock) | бесконечно, остановить `Ctrl+C` |
| `-- deadlock-fixed` | исправление: одинаковый порядок захвата | 2 с |
| `-- deadlock-timeout` | обнаружение через `Monitor.TryEnter` с тайм-аутом | 4 с |
| `-- mutex` | именованный Mutex (запустить в **двух** окнах терминала) | ждёт Enter |
| `-- p2t1` … `-- p2t5` | часть 2, задания 1–5 | 1–10 с |
| `-- variant` | индивидуальное задание, вариант 2 (фильтрация PLINQ) | 3 с |

`-- p2t2` в конце просит ввести число для интерактивного поиска (например `777`), для выхода введите `exit`.

## Как показать deadlock в Visual Studio (по методичке)

1. Откройте `Lab5.csproj`, в `Program.cs` временно запустите режим `deadlock`: *Свойства проекта → Отладка → Аргументы* = `deadlock`.
2. Запустите с отладкой (**F5**). Программа выведет `Thread1: захватил lockA`, `Thread2: захватил lockB` и зависнет.
3. **Debug → Break All** (Ctrl+Alt+Break).
4. **Debug → Windows → Parallel Stacks** – граф стеков потоков.
5. **Debug → Windows → Threads** – потоки в состоянии ожидания.
6. **Debug → Windows → Call Stack** – где остановился поток (строка с `lock`).
7. Сделайте снимки этих окон для отчёта.

## Что изменено относительно кода методички

| Что | Почему |
|---|---|
| `WaitAsync(500)` вместо `WaitAsync()` в Producer-Consumer | в оригинале после остановки потребители ждут семафор вечно, `Task.WaitAll` не возвращает управление |
| размер буфера и число потоков – параметры `Run` | чтобы выполнить задания 2 и 3 без правки кода |
| `using System.Collections.Concurrent;` | без него `Partitioner` не компилируется |
| убран `Console.ReadKey()` и бесконечный цикл при `null` в задании 2 | иначе программа падает/зависает при перенаправленном вводе |

Остальной код методических указаний сохранён без изменений.
