# ССП-5. Теория кратко (шпаргалка)

| Понятие | Одной фразой |
|---|---|
| Поток / Task | рабочая единица; у потока свой стек, куча общая |
| Гонка данных | два потока меняют одно и то же без защиты, результат непредсказуем |
| Критическая секция | код, который должен выполняться одним потоком |
| `lock` | взаимное исключение внутри процесса |
| `Mutex` | то же, но может быть именованным (между процессами), знает владельца |
| `Semaphore` | счётчик разрешений, пускает до N потоков |
| Producer-Consumer | `empty` (свободные места) + `full` (занятые) + mutex на буфер |
| Deadlock | потоки ждут ресурсы друг друга по кругу |
| Лечение deadlock | одинаковый порядок захвата; тайм-аут `TryEnter`; меньше блокировок |
| Голодание | поток не получает ресурс, остальные работают; не deadlock |
| Китайцы и палочки | китайцы = потоки, палочки = ресурсы, рис – не ресурс; отпускать ресурсы по порядку |
| `Parallel.For/ForEach` | параллельные циклы, итерации независимы |
| Локальные переменные потока | накопить у себя, синхронизировать один раз в конце |
| PLINQ | `AsParallel()`; `AsOrdered()` сохраняет порядок; не всегда быстрее |
| `Partitioner` | свои блоки разделения данных |
| `CancellationToken` | отмена параллельной операции |

**Главные цифры нашего запуска:** `lock` на каждой итерации – 1239 мс, последовательно – 110 мс, локальные переменные – 42 мс; PLINQ на простых операциях – медленнее LINQ, на проверке простоты чисел – быстрее в 4,6 раза.
